# Claim chat P2-2026 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the P2-2026 claim submission design changes to the claim chat: animated loading text, a corrected summary answer hierarchy, a bottom-sheet insurance picker, a redesigned input mode row with glass overlays, a genuinely sticky input, and Ghost skip buttons.

**Architecture:** Everything lands in `app/feature/feature-claim-chat`, a KMP module whose only consumer is Android. New code goes in `commonMain` and stays platform-agnostic; anything needing a JVM-only or Android-only dependency goes in `androidMain`. Each item gets its own branch off `develop` and its own draft PR. Items 1, 2 and 5 touch disjoint files and run in parallel; 6a then 6b run in sequence; 7 runs last.

**Tech Stack:** Kotlin Multiplatform, Compose Multiplatform, Metro DI (`dev.zacsweers.metro`), Apollo GraphQL, Arrow `Either`, assertk + kotlin-test + Turbine for tests.

**Spec:** `docs/superpowers/specs/2026-09-11-claim-chat-p2-2026-design.md`

```kotlin
package com.hedvig.android.feature.claim.chat.ui.step

import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.produceState
import androidx.compose.runtime.rememberUpdatedState
import androidx.compose.runtime.snapshotFlow
import kotlin.time.Duration
import kotlin.time.Duration.Companion.milliseconds
import kotlinx.coroutines.delay
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.channelFlow
import kotlinx.coroutines.flow.first
import kotlinx.coroutines.launch

/**
 * Walks [descriptions] one at a time, holding each for at least [minimumDwell] before moving on.
 *
 * The backend can deliver several descriptions in a single poll. Rendering only the most recent one would skip the
 * ones in between, so this advances through the backlog in order rather than jumping to the end.
 */
internal fun pacedDescriptions(descriptions: Flow<List<String>>, minimumDwell: Duration): Flow<String> = channelFlow {
  val known = MutableStateFlow(emptyList<String>())
  launch { descriptions.collect { known.value = it } }
  var shown = 0
  while (true) {
    // Suspends until something new is available, so an idle task step costs nothing.
    val available = known.first { it.size > shown }
    send(available[shown])
    shown++
    delay(minimumDwell)
  }
}

/** Compose entry point. Returns the description that should currently be on screen, or null before the first. */
@Composable
internal fun rememberPacedDescription(
  descriptions: List<String>,
  minimumDwell: Duration = 900.milliseconds,
): String? {
  val latest by rememberUpdatedState(descriptions)
  return produceState<String?>(initialValue = null) {
    pacedDescriptions(snapshotFlow { latest }, minimumDwell).collect { value = it }
  }.value
}
```
